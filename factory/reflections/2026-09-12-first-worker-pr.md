# First worker PR: execution evidence and context limits

Development-session observation, 12 September 2026. This is not Remi's usefulness judgment or an automatically activated factory rule.

## What happened

The native Eve worker produced [PR #2](https://github.com/software-factory-workshop/jira-clone/pull/2), implementing proposal usefulness feedback. The host verified the diff and required checks before publishing. The independent reviewer is a separate station with fresh source snapshots and no publishing tool. It recorded approval with a nonblocking stale storage-warning finding after independently passing checks. Research and API decisions are recorded in [work-stations.md](../work-stations.md); exact run evidence is in [verification.md](../../docs/verification.md).

The worker initially spent its allowance reading files and reasoning about component choices. It needed budget continuations and an explicit instruction to start implementing. Actual file writes, passing checks and a published PR eventually established delivery; its earlier narrative did not. A resumed native sandbox preserved work without copying code into a new harness.

## What we changed

The next worker receives concrete existing control choices, a bounded initial exploration allowance, and compact dependency-setup output. The task and active-work documents now distinguish an assigned implementation from a proposal awaiting judgment. The cockpit follows the background specialist after the dispatcher's own turn finishes and treats a recorded result as stronger evidence than historical budget prompts.

## What remains unproven

The reviewer initially placed its absent browser checks in limitations, which prevented approval; it then classified them as optional under the task's explicit allowance to list unrun checks and disclosed them in its summary. That judgment is visible evidence to assess, not proof that the host can decide whether every omitted check matters.

A fresh worker has not yet demonstrated that these context changes eliminate over-investigation. This first run was assisted. Passing builds and tests do not establish user taste, browser behavior or review quality. Browser verification of PR #2 is recorded separately; a reviewer verdict applies only to the captured source revisions and does not authorize merging.

## Next measurement

On the next useful assignment, keep the same cheap model and native station. Measure reads before first edit, actual checks, interventions, time and model cost, and whether an independent reviewer finds a material defect. Change one context weakness at a time. Do not build another orchestration layer merely because this first run needed steering.
